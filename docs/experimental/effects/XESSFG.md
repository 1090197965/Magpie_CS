# XeSSFG（068 local 实验版本）

效果选择器只提供一个 XeSSFG，倍率可选 2×～4×。新建时默认 2×、AMD 光流、质量。

首次启动本次新版 068，会将所有效果组里的旧 x2/MFG 替换为统一效果器。迁移倍率为 2×，光流方法和质量保留原选择；缺失字段使用旧效果器默认语义。原效果组、配置文件引用、其他效果顺序及缩放属性保留。同组重复 XeSSFG 保留第一个。迁移前自动备份，保存失败不完成启动迁移。今后导入旧效果组也执行转换，新效果器已经保存的参数不会再次重置。

2×和 Intel 原生路径使用 SDK 原行为。非 Intel 显卡的 3×/4×自动启用多帧兼容及节奏修复，没有额外兼容开关。3×/4×目前支持无光流或 AMD 光流；NVIDIA 光流用于 2×。未知运行库、已被修改的补丁位置或初始化失败会明确报错，不将请求倍率静默改为 2×。

兼容路径限定随附 `libxess_fg.dll 1.3.1.78`，SHA-256 为 `EC5E0C65E075570C6EDE72618BB666D0BE0C2E10B2EA9762C0FE8CB8E375AB27`。应用只修改内存，并在交换链、XeFG/XeLL 上下文退出后恢复；无法确认退出或恢复成功时，本进程停止接受新的 XeSSFG 会话，需要重启 Magpie。

验证范围：RTX 5070 Ti 上的 SDR、零运动向量合成画面，在同一进程中执行 2→3→4→2→4→2。每轮预热后 35 次提交，SDK 分别返回 70／105／140 帧，35 次均为完整倍率；逐生成帧 hook 已实际执行，退出后原生 2×恢复单插帧能力。配置迁移、补丁故障回滚、时间估计和选择器另有自动回归测试。

这些结果不证明显示器已均匀显示全部生成帧。日志中的 provider 间隔和 SDK 计数用于排查，不能替代 ETW／PresentMon 的显示事件。实际捕获链的 AMD/NVIDIA 光流、HDR、VRR、30/45/60 FPS 波动输入、长时间运行、游戏遮挡和 HUD 画质仍需实测；本次以实验版本交付。5×～8×未开放。
